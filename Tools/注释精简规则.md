> 本文件是**早期一轮**注释清理时写的操作规则，现已作废。保留仅为历史参考，**不要按它执行**。
> 现行唯一权威：**[`Docs/注释规范.md`](../Docs/注释规范.md)**；机器判据：`pwsh Tools/comment-lint.ps1`。

## 为什么作废（两处硬冲突）

| 本文件旧口径 | 现行口径（`Docs/注释规范.md`） |
|---|---|
| §硬规矩：「不许改 XML 标签语法：`/// <remarks>`、`<para>`、`<see cref="…"/>` 的写法保持原样」 | §4.1：**标签白名单只有 `<summary>` / `<remarks>`**；`<para>`、`<c>`、`<see cref>`、`<param>`、`<returns>`、`<inheritdoc>` 等**必须物理删除**，`<see cref="X"/>` 降级为纯文本 `X` |
| 目标：「该批注释行数压到总行数的 **10%** 以下」（行数占比） | §5.1 / §5.2：按**注释有效字符**计，逐文件登记**预算上限**（`Tools/comment-budget.json`），新增文件按密度上限 5.37 字符/代码行 |

两者不是同一套度量，混用会得出互相矛盾的结论（行数占比低的文件完全可能字符超支）。

## 仍然有效的部分（已并入新规范）

- 「第一性判据」→ 新规范 §1（要求写注释前先回答一个具体问题），措辞已收紧为
  「编译器不会拦、测试不会红、只表现为手感 / 观感 / 性能错」。
- 「优先删：变更史与自我辩护 / 复述代码的 `<param>` / 多行 `<remarks>` 散文 / `<para>` 堆砌的未采纳方案 /
  装饰性分隔横线」→ 新规范 §3 的 `背景论证`、`重复复述`、`排版标签` 三类的部分内容。
- 「必须留：不报错 / 静默 / 数值口径 / 单位 / 帧序与唯一调用方 / 一次性 vs 持久」
  → 新规范 §2 的第 1、3、6、8 类。
