### 一、切图与导入规范（硬性）

1. **PPU (Pixels Per Unit)：`100`**。全仓美术件（`art/Character`、`art/Prop`、`art/Background`、`demo/Square.png`）当前都是 100，别改成 128。
   - **1 世界单位 = 1 格 = 100 像素**：`Grid.CellSize = (1,1,0)`（XY 布局），`demo/Square.png` 恰好 100×100 像素 ⇒ 正好铺满一格（它同时是 19 张状态贴图的占位 sprite 与 `Tile_Floor` 的 sprite）。
   - **图幅按 100 的整数倍出**：现有角色图是 `idle 512×1024`、`walk 1024×1024`、`gun 512×256`、`die 256×256`，都是 100 的整数倍，单帧宽度取 100 的约数（一个身位 ≈ 100×100 像素）。**格子对齐由策划摆位置，别靠改 PPU 去凑格子**（那样会把所有关卡贴图一起缩放）。
2. **Filter Mode**：像素画选 `Point`（`filterMode: 0`，`demo/Square.png` 就是这个）；手绘/矢量选 `Bilinear`（`filterMode: 1`，现有角色与道具件都是它）。
3. **Compression**：选 `None` 或 `Normal Quality`（现有件为 `textureCompression: 1`）。
4. **Pivot 对齐约束**：
   - **角色：`Center (X: 0.5, Y: 0.5)`**。现有角色件全是 `alignment: 0` + `spritePivot: (0.5, 0.5)`，**别改成 Bottom**：Y-Sort 与格子登记用的都是角色的**物理体中心**（`EnemyActor` 用 `BoundsArea` 的圆心算 `Position.y`，`GridLogic.WorldToCell` 也拿这个点），`ActorMotor` 的 `BoundsArea` 碰撞体同样是圆心。改成 Bottom 会让贴图整体上浮半个身位，与碰撞体、格子判定错位，且不报错。
   - **地块瓦片与 UI**：`Center (0.5, 0.5)`（同现状）。
   - **贴地道具**（喷泉、机器等）：`Center (0.5, 0.5)`，用物体自身的 y 参与 Y-Sort，不要靠 pivot 抬底。
5. **Sprite Mode**：现有角色图是 `spriteMode: 1`（Single）。若一张 PNG 里有多帧，**要么在导入设置里改 Multiple 并切好帧，要么让美术出单帧图**；当前仓库里的角色图都还是 Single，直接"切片"是切不出来的。

### 二、地块 TileBase 归档规约（约定懒加载）

- **归档路径**：必须放入 **`Assets/Resources/tiles/`**。
- **文件命名**：必须严格命名为 **`Tile_<TileStateType 枚举名>.asset`**。

#### 19 种合法地块文件名速查（直接复制命名）

对应 `cfg.dso.TileStateType` 里除 `None` 外的 19 个值（`Normal` 也要有一份，效果层的"回到原样"会用到）：

```text
Tile_Normal.asset               Tile_Mud.asset                  Tile_MudSkid.asset
Tile_Smoothie.asset             Tile_Freeze.asset               Tile_TerracottaBrick.asset
Tile_FrozenEarth.asset          Tile_Steam.asset                Tile_ConductElectricity.asset
Tile_Vine.asset                 Tile_Glass.asset                Tile_Burn.asset
Tile_Ashes.asset                Tile_BasicWater.asset           Tile_BasicEarth.asset
Tile_BasicFire.asset            Tile_BasicIce.asset             Tile_BasicElectricity.asset
Tile_BasicPlant.asset
```

> *规则*：文件名对了，运行时 `TilemapAdapter.TileFor` 按 `tiles/Tile_<状态>` 约定的 `AssetModule.Load<TileBase>` 自动寻址，**场景 Inspector 不用连线**。19 个状态一个不缺（缺哪个状态就在变它时刷一条 `[Grid] 未找到地块资源: tiles/Tile_X` 警告，那格静默不显示覆盖贴图）。

#### 🔴 文件名的 `Tile_` 前缀 vs 资产内部名（两条通道，别只记一条）

- **效果层贴图**（`TileFor`）：认**文件路径** ⇒ 文件名必须是 `Tile_<状态>`。占位件与正式件都用这条。
- **InitialSetup 笔刷层**（`ResolveSetupState`）：认**贴图的资产名 `tile.name`**（Unity 里它是资产 yaml 里的 `m_Name`）。解析顺序是**先剥 `Tile_` 前缀再解析、失败后拿全名再解析**。
- 现状：`Resources/tiles/` 下 19 张状态贴图的 `m_Name` 都是**不带前缀**的（`Tile_Mud.asset` 的 `m_Name` 是 `Mud`），靠第二条通道命中；`resources/tiles/tilesets/demoTile/` 里的 `Tile_Floor` / `Tile_Mud` 则 `m_Name` 带前缀，靠第一条命中。**两条都必须保留**，删掉任一条都会让笔刷刷上去的泥浆静默落回 `Normal`。
- 稳妥做法：**文件名与资产内部名都写全 `Tile_<状态>`**（新建资产时 Unity 默认就用文件名当 `m_Name`，别手动改短）。两边都带前缀时第一通道直接命中，第二通道根本不跑。

> **同名件别拿错**：`tiles/Tile_Mud.asset`（19 连占位件之一，灰方块染色，内部名 `Mud`）与 `tiles/tilesets/demoTile/Tile_Mud.asset`（正式美术件，内部名 `Tile_Mud`）**文件名一模一样**，只有内部名能区分。调色板 `Assets/Resources/palettes/Demo_Palette.prefab` 引用的是 **demoTile 那份**；场景里接线也应用它，用错现场表现为"泥浆是个纯色方块"，不报错。

### 三、场景 Tilemap 三层装配标准

在场景的 `Grid` 节点下保持三层结构：

```text
Grid                (Cell Size = 1, 1, 0；Cell Layout = XY；Cell Swizzle = 0)
├── Ground          (TilemapRenderer Order = 0)  ← 地板层（必须刷满常规地板，提供合法走行动线）
├── InitialSetup    (TilemapRenderer Order = 1)  ← 关卡编辑层（笔刷画开局泥浆/火池/冰面，运行时读完自动 SetActive(false)）
└── TileEffect      (TilemapRenderer Order = 2)  ← 动态反应层（运行时状态覆盖层，开局留空）
```

- **Grid 本体**：`CellSize` 必须 `1 × 1`（`TilemapAdapter.ReadGeometry` 对非正方只报错不修：`格子不是正方形（x × y）…几何按 x 取值`）、`Cell Swizzle = 0`、位置留在整数（`Grid` 与两个 Tilemap 的 Transform 若被挪到小数坐标，`WorldToCell` 与 `CellCenter` 会静默错半格）、缩放 `1`、不旋转。Tilemap 的 `Tile Anchor` 保持默认 `(0.5, 0.5)`——`GridGeometry.CellCenter` 按"格中心 = 原点 + (格号+0.5) × 格边长"算，而 `ReadGeometry` 会拿 `GetCellCenterWorld((0,0))` 跟它比对一次：对不上直接报 `[Grid] 格子几何自检失败…检查 Grid 的 Cell Size / Tile Anchor`。锚点一改，投掷落点高亮与实际效果格就整体错开。
- **`TilemapAdapter` 接线**：
  - `groundTilemap` 拖入 `Ground`（**必接**，`IsWired` 只看它）。
  - `effectTilemap` 拖入 `TileEffect`（**必接**，状态贴图盖这层）。
  - `initialSetupTilemap` 拖入 `InitialSetup`（可选，见下）。
  - `stateTiles` 数组**保持为空**（自动走约定的 `tiles/Tile_*.asset`）。
- **三层不得指向同一个 Tilemap**：`TilemapAdapter.Awake` 会报错。`groundTilemap` 与 `effectTilemap` 同层最坏（状态结束时会连地板一起擦掉，地上出现空洞）；`initialSetupTilemap` 指错层最隐蔽（它读完会 `SetActive(false)`，开局把地板或效果层整个关掉，现象离病因很远）。
- **`InitialSetup` 是可选的**：不建该层，初始地块退回 `tile_initial` 表驱动。建了就必须单独一层且接进 `initialSetupTilemap`，否则你画的笔刷不生效且不报错。
  - 笔刷只能刷在**有地板的格**上：`LoadInitialSetupTiles` 对没地板的格报 `[Grid] InitialSetup 层在格 (x,y,z) 刷了地块，但这一格没有地板` 并忽略（两张 Tilemap 必须挂在同一个 `Grid` 下，否则坐标对不上）。
  - 它读完就隐藏，`TilemapRenderer Order` 填几都无所谓，按上表填 1 即可。

### 四、角色 Animator 控制器快速构建

角色的 View 子节点上还需要 `SpriteRenderer` 与 `ActorAnimationView`（`Presentation/Visual/ActorAnimationView.cs`）。

#### 4.1 挂载（Root-View 两层，别挂错节点）

```text
Player / Enemy        ← Root：Rigidbody2D + Collider2D + PlayerMotor/EnemyMotor + PlayerController/EnemyActor
└── View              ← localPosition 必须 (0,0,0)
    ├── SpriteRenderer
    ├── Animator      ← 本节产物挂这里
    └── ActorAnimationView
```

- **`Animator` 与 `ActorAnimationView` 都挂 `View`，不要挂 Root。** 将来受击抖动/后坐力/伪高度只改 `View.localPosition`；挂在 Root 上，抖动会和刚体位置打架。
- `ActorAnimationView` 的 `animator` / `spriteRenderer` 字段留空即可（`Awake` 用 `GetComponent` 从**本节点**自愈抓取；它**不会**往父级找，所以两者必须在同一个 `View` 上）。
- **`ActorAnimationView.useFlipX` 保持关闭**：`ActorMotor.Facing` 已把左右朝向落成 **Root 的 `localScale.x` 符号**，View 是 Root 的子节点，两条镜像叠在同一根 x 轴上会互相抵消（角色朝左反而显示成朝右，不报错）。同理 **动画美术不要自带左右翻转**。
- 敌人不用手工建：`EnemyActor` 运行时造 `View`（`Enemy` 下还会多一个 `HpText` 兄弟节点）。

#### 4.2 建立剪辑

把切好的帧拖进场景生成 `.anim`（采样率 12~15，循环动作勾 `Loop Time`）。现有可用图：

| 图 | 建议剪辑 |
| :-- | :-- |
| `art/Character/character_player_idle.png` | `Player_Idle.anim`（Loop ✓） |
| `art/Character/character_player_walk.png` | `Player_Walk.anim`（Loop ✓） |
| `art/Character/character_player_gun.png` | `Player_Throw.anim`（Loop ✗） |
| `art/Character/character_player_die.png` | `Player_Die.anim`（Loop ✗，播完停在末帧） |

#### 4.3 参数契约（`Presentation/Visual/AnimHashes.cs`，名字逐字符一致）

代码只按这些哈希推参数，名字写错**不报错**，表现为动画永远不切：

| 类型 | 参数 | 用途 |
| :-- | :-- | :-- |
| Float | `Speed` | 速度标量（单位/秒），Idle/Walk 混合 |
| Float | `MoveX` / `MoveY` | 本帧归一化移动方向，8 向混合树用 |
| Float | `FacingX` | 朝向水平分量，站住时也要保留 |
| Trigger | `Hurt` / `Die` | 受击 / 死亡（玩家与敌人共用） |
| Bool | `IsDashing` | 玩家冲刺（有持续段，故用 Bool） |
| Bool | `IsHurt` | 敌人受击僵直 |
| Trigger | `TriggerThrow` / `TriggerPlant` | 玩家投掷出手 / 放置 |
| Trigger | `Attack` | 敌人近战出手 |
| Trigger | `Impact` / `Collect` | 掉落物落地 / 被领取 |

#### 4.4 最小状态机（先跑通走跑）

1. 新建 `PlayerAnimator.controller`，加 Float 参数 `Speed`。
2. `Idle` ➔ `Walk`：条件 `Speed > 0.01`，**取消勾选 `Has Exit Time`**，`Transition Duration = 0`。
3. `Walk` ➔ `Idle`：条件 `Speed < 0.01`，**取消勾选 `Has Exit Time`**，`Transition Duration = 0`。
4. 把 controller 拖给 `View` 的 `Animator`。
5. **`Controller` 留空是合法配置（白模期）**：`HasValidAnimator` 为假时所有动画调用是安全 no-op，零报错零警告，`SpriteRenderer` 与 Y-Sort 照常工作。**没接 controller 时不要指望有动画，也别因此加警告日志。**

### 五、装配完成自检清单

- [ ] 角色贴图 PPU = 100，角色帧 Pivot = Center (0.5, 0.5)，地块/UI Pivot = Center。
- [ ] 多帧图确实切成 Multiple 并切好帧（或每帧一张单图）：`spriteMode` 不是 Single 就是漏切了。
- [ ] 地块资产落在 `Assets/Resources/tiles/`，文件名 `Tile_<状态>` 与 19 个枚举逐字符一致，且资产内部名也带 `Tile_` 前缀。
- [ ] 场景 `Grid` 下 3 层 Order 分别为 `0`, `1`, `2`，`Cell Size = (1,1,0)`，`Tile Anchor = (0.5, 0.5)`，`Ground` 层已刷有地板。
- [ ] `TilemapAdapter` 三个 Tilemap 字段指向三个**不同**的层，`stateTiles` 为空。
- [ ] `Animator` 与 `ActorAnimationView` 在 `View` 子节点上，`View.localPosition = (0,0,0)`，`useFlipX` 未勾选。
- [ ] Animator 参数名与 4.3 表逐字符一致（`Speed` / `MoveX` / `MoveY` / `FacingX` / `Hurt` / `Die` …）。
- [ ] 进入 PlayMode，Console **无** `[Grid] 未找到地块资源`、**无** `InitialSetup 层在格…没有地板`、**无** `ActorAnimationView` 相关警告；角色走跑切换无滑步延迟，左右转身方向正确。
