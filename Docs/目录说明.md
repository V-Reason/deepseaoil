本目录树是**人工维护**的快照，没有机器校验（原先那条「写进来的每个路径都必须真实存在」的测试已删：删一个美术目录就红，代价大于收益）。改目录结构时请顺手同步本节。

## 命名约定

- **层与层之间已有 asmdef 边界**（拓扑与守卫见 [`架构约束.md`](架构约束.md)）：`DeepseaOil.Foundation` / `.Data` / `.Logic` / `.Presentation` ＋ `cfg` / `DeepseaOil.Generated.Input` / `DeepseaOil.Tests.EditMode` / `DeepseaOil.Tests.Scene`。`cfg.asmdef` 刻意放在 `Scripts/Generated/` 而**不是** `Generated/Config/` —— 后者是导表镜像覆盖区，asmdef 放进去下次导表必被静默删除，边界随之塌掉。`Assets/` 下的源码**全部**归 asmdef，预定义程序集（`Assembly-CSharp`）残留为零。
- 命名空间 = 目录名，四个例外（这些目录落**上级**命名空间）：`Logic/Actor[.States|.Status]`、`Logic/Bounds/`、`Logic/Input/GameState.cs`、`Presentation/Root|Audio/`、`Presentation/IDrivenEntity.cs|ISceneRoot.cs`。（`Presentation/UI/MonoMgr.cs` 原先也是例外之一，已随死代码清理删除。）
- 另有四处**名字不同**：`Logic/Event/` → `.Events`（复数）、`Logic/Services/` → `.Service`（单数）、`Presentation/Diagnostics/`（**不能**叫 `Debug`：`DeepseaOil.Presentation.Debug` 会让本层所有 `Debug.LogError` 变成 CS0234）。
- 只有 `GameRoot` 是真单例（同时是全工程唯一常驻 `MonoBehaviour` 与协程宿主）；`MonoMgr` 那个"临时例外"已于 2026-10 拔除。进程级件（UI / 音频 / 游戏状态 / Data 层）一律由 `GameRoot` 装配并持有。

## 生成物禁区

放这些位置的手写文件会被**静默删除**——不报错，下次生成后就不见了。

| 目录 | 谁生成 |
| :-- | :-- |
| `Assets/Scripts/Generated/Config/` | Luban 导表 |
| `Assets/StreamingAssets/Luban/` | Luban 导表 |
| `Assets/Scripts/Generated/Input/InputSys.cs` | Input System 生成 |

不可动：`Assets/Resources/**`、`Assets/Editor/**`、`Tests/Runtime/Editor/` 的末级 `Editor`。
`ConfigWorkspace/Tools/Luban/` 是 Git LFS 内容（`*.dll` / `*.exe`），**不要装 Luban 的 UPM 包**：与本地拷贝撞名，整个工程都编译不出来。
