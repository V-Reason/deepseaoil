## 第 1 节 · 如何一键跑通验证

### 1.1 打开场景并 Play

| 步 | 动作 |
| :-- | :-- |
| 1 | Unity 打开本工程（2022.3.62f3c1 LTS，URP 2D） |
| 2 | 打开场景 **`Assets/Scenes/Official.unity`** —— 全工程**唯一**装配了完整玩法链的场景 |
| 3 | 按 **Play**（不需要进 Build Settings：那三处场景列表是空的，本工程目前只在编辑器里跑） |

> `Official.unity` 就是主场景（`Empty.unity` 是空白件，`Assets/Scenes/Sandboxes/*` 是切片沙盒，见 §1.5）。
> 它直接挂了 `GameRoot`（组合根）＋ `InputProvider` ＋ `TilemapAdapter` ＋ `BoundsArea` ＋ 三层 Tilemap，
> 并以**预制体实例**摆入 `CombatRoot`（战斗切片）＋ `Player` ＋ 三个 `Fountain`（`kind` = 0 水井 / 1 土丘 / 2 生命神泉）＋ `Virtual Camera`。

### 1.2 Play 之后的 Console 应该长这样（三条）

```text
[Config] initialized, tables loaded from: <...>/StreamingAssets/Luban
[Grid] 从 InitialSetup 层成功载入 24 个初始特殊地块。
[Combat] 装配完成：格子 N 个（初始状态 24 个），球种 2 个，泉眼 3 个（生命神泉 1 个），反应规则 11 条，二级反应 6 条，回血静止 3 秒，敌人 启用
```

只要这三条都在，**配置链路 / 网格 / 战斗切片就都装配成功了**。任何一条缺失或变成红色 `LogError`，
按它的前缀定位：`[Config]` 看配表，`[Grid]` 看场景 Tilemap 三层结构，`[Combat]` 看 `CombatRoot` 的 Inspector 接线。

### 1.4 🔴 最短验证路径（一步就能看见"离散反应"生效）

场景里**预先刷好了一片 6×4 的「基础火池」**（橙色方块，24 格），坐标 x∈[-1,4]、y∈[-6,-3]。
走到它旁边，然后：

| 你做什么 | 应该发生什么 | 依据 |
| :-- | :-- | :-- |
| **鼠标左键**朝橙色格投水球 | 那一格**变成近白色**（蒸汽，`Tile_Steam`），格上的敌人**掉 2 血并被推开 3 格** | `element_rule` #4：基础火池(16) + Water → 蒸汽(8)，`impact_damage 2` / `impact_knockback 3` |
| **鼠标右键**朝橙色格投土球 | 那一格**变成陶土色**（陶砖，`Tile_TerracottaBrick`），敌人被推 1 格 | `element_rule` #5：基础火池(16) + Earth → 陶砖(6) |
| 朝普通灰地投水球 / 土球 | 该格变成**蓝色**（基础水）/ **棕色**（基础土） | 兜底：空地 + 水 / 土 |
| 再朝蓝色格投土球 | 变成**深棕**（普通泥浆） | `element_rule` #2：基础水(14) + Earth → 普通泥浆(2) |

> **地块状态靠颜色区分**：17 个 `Tile_*.asset` 共用一张白色占位精灵，**颜色写在各自的 `m_Color` 里**。
> 所以"全是色块"是刻意的占位美术，不是没接线。换正式贴图见 §2.5。
>
> ⚠️ **`[Reaction]` 日志在这个场景里是关的**。`ReactionResolver.TraceEnabled` 默认 `false`，
> 只有两个沙盒 Harness 会把它置 `true`。想在主场景看每次落地的裁决明细（命中哪条规则 / 走没走兜底），
> 把 `ReactionResolver.cs:15` 的 `TraceEnabled` 临时改成 `true`，或在 `CombatRoot` 装配后加一行赋值。

## 第 2 节 · 核心架构入口速查

四层单向依赖：`Presentation ➔ Logic ➔ Data ➔ Foundation`。asmdef 引用**不传递**，
跨层用到基类/接口时必须显式补引用（踩过的坑见 [`架构约束.md`](架构约束.md)）。

### 2.1 组合根 · `Assets/Scripts/Presentation/Root/GameRoot.cs`

全工程**唯一真单例**（`DontDestroyOnLoad`）、唯一常驻 `MonoBehaviour`、协程宿主。
所有驱动收敛在它的 `Update` / `FixedUpdate`，**业务组件不许自己写 `Update`**。

- `BuildDriveSteps()` 把驱动顺序写成数据：⓪ 场景根装配 → ⓐ 输入采样 → ⓑ UI 输入 → …（加阶段是加一行）
- 服务装配顺序 `[Pause, Scene, Save, Audio, Timer]` **既是 Init 序也是 Tick 序**
- 场景系统实现 `ISceneRoot` 并声明 `Order`，由 `GameRoot` 拓扑编排推进

### 2.2 战斗切片 · `Assets/Scripts/Presentation/Root/CombatRoot.cs`

战斗这一块的**组合根**：把 `PlayerController`、`TilemapAdapter`、三个 `Fountain`、球种表、
反应规则、波次、掉落全装配起来，然后交给 `GameRoot` 驱动。

- `Attach()` 是装配入口；装配完打那条 `[Combat] 装配完成：…` 日志
- `fountains` / `player` / `gridView` 是 Inspector 必接项；`ballRoot` / `actorRoot` 留空会回落到自身
- 每帧推进格子与敌人；`enableWaves` 控制是否刷怪

### 2.3 反应入口（本作的核心机制）· 三个文件

| 文件 | 职责 |
| :-- | :-- |
| `Assets/Scripts/Logic/Element/ReactionResolver.cs` | **一级反应裁决**：`(原格状态, 球种)` 双键查表 → `(新地貌, 伤害, 击退, 麻痹, 是否连锁)`。纯函数，不读写世界。未命中走兜底（空地+水/土） |
| `Assets/Scripts/Logic/Grid/TileChainReactor.cs` | **网格连锁泛洪**：火（可燃）沿可燃物燎原、电（导通）沿 `is_conductor` 泛洪。起点自己必须满足条件 |
| `Assets/Scripts/Logic/Grid/TileStateMachine.cs` + `States/TableTileState.cs` | **地貌自身行为**：`duration` 到期回空地、`slow_rate` 减速、`dot_damage` 每秒伤害 |

数据侧统一走 `Assets/Scripts/Data/Config/ConfigModule.cs`（Data 层唯一取值口，
上层只用 `GetXxx` 与 `*Spec` 包装件，不碰生成行）。

### 2.4 配表链路（改数值的唯一正道）

```text
ConfigWorkspace/Data/*.xlsx          ← 策划手改这里（枚举列用中文别名 + 下拉框）
        │  Unity 菜单 Luban ▸ 表格数据导入           （= Luban --strict 导出到 ConfigWorkspace/output/）
        ▼
Assets/Scripts/Generated/Config/     ← 生成的 C#（禁手改）
Assets/StreamingAssets/Luban/        ← 生成的 JSON（禁手改）
```

> 🔴 **两个生成物目录会被镜像清空重写**，手写文件放进去必丢。
> `cfg.asmdef` 是刻意留在 `Generated/` 上一级的手写件，**别挪进 `Generated/Config/`**。
> 校验模式必须同时加 `-f` 和 `-x outputSaver=null`（否则 Luban 会照写盘）。

### 2.5 表现层常改的几处

| 想改什么 | 去哪 |
| :-- | :-- |
| 地块贴图 | `Assets/Resources/tiles/Tile_<枚举成员名>.asset`（**顶层，别建子目录**） |
| 地块配色 | 各 `Tile_*.asset` 的 `m_Color`（共用一张白色占位精灵） |
| 手感（移速 / 抛物线 / 击退 / 闪烁） | `Assets/Resources/tuning/*.asset` 与 `config/PlayerConfig.asset`，**Play 时改即时生效** |
| 颜色总表 | `Resources/tuning/VisualPalette.asset` |

> 🔴 **造 Tile 资产有两条硬约束，违反都不报错，只表现成「贴图不显示」。**
> 新增地块贴图必须落在 `Assets/Resources/tiles/` **顶层**、且命名为 `Tile_<TileStateType 成员名>`，
> 因为 `TilemapAdapter.TileFor` 的懒加载 key 写死为 `tiles/Tile_{state}`（`TilemapAdapter.cs:297`）。
> 放进子目录或换成别的命名，`TileFor` 一律找不到（**只警告一次就返回 null**）；
> （`tiles/Ground/` 是背景 tileset 切图，不走这条约定，由 Ground 层直接引用。）
> `InitialSetup` 层的地貌解析也走同一套名字约定（先剥 `Tile_` 前缀再 `Enum.TryParse`，`TilemapAdapter.cs:170-185`），
> 解析失败会打一条警告并把该格当普通地板。**唯一例外**是 Inspector 的 `stateTiles` 特例覆盖表 ——
> 想用自定义命名或子目录，就得给每个状态手工配一行。

> 🔴 **别往 Tile Palette 里拖「图集」。** 拖一张多格图集（`Sprite Mode = Multiple`，例如 120 格的
> `Assets/Resources/art/Background/tileset_wasteland_base.png`）进去会自动批量生成 Tile 资产，
> 而**这条路径必崩编辑器**：`TileDragAndDrop.ConvertToTileSheet` 在 `sheet.Count > 1` 时调用
> `EditorUtility.SaveFolderPanel`（**Windows 原生文件夹选择框**，
> `Library/PackageCache/com.unity.2d.tilemap@1.0.0/Editor/TileDragAndDrop.cs:359`）。
> 原生对话框会把**进程当前工作目录**改成它浏览到的目录，Unity 随后在 `AssetDatabase.StopAssetEditing()`
> （同文件 `:486`）处检出「CWD 已不是工程根」→ **Fatal 弹窗、编辑器直接退出**，
> 此时 `StartAssetEditing` 批处理被拦腰打断，目标目录里只留下零星几个 Tile（实测 120 格仅活下来 1 个）。
> 这是 Unity 包自身的缺陷，**改动发生在原生层**（该包托管代码里没有任何修改 CWD 的调用），
> 不要在 `Assets/` 下找自己的代码背锅。
>
> - ✅ **安全做法**：一次只拖**单张 sprite** —— `sheet.Count == 1` 会走 `SaveFilePanelInProject`（`:412`，Unity 自带面板，不碰 OS 对话框）。
> - ✅ **最安全**：拖**已经存在的 `Tile_*.asset`** —— `:342` 提前 return，零对话框。
> - 🧹 崩过之后的现场处理：`Temp/UnityLockfile` 可能残留（陈旧锁，未被进程占用时无害）；
>   残缺的 Tile 目录要整个删掉重做，并逐个确认有配对的 `.meta`（少了 `.meta` 会让引用静默丢失）。

## 第 3 节 · 接手后建议的前 3 项工作

### ① 把三道门禁变成"一条命令"，并接进 CI

工程已经有可靠的自检，但**全靠人记得跑**：

```powershell
pwsh Tools/compile-gate.ps1 -Topology   # 0 错误 / 0 警告，含四层拓扑反向依赖检查
pwsh Tools/comment-lint.ps1             # 注释预算 + XML 标签白名单，退出码 0 = 通过
pwsh Tools/luban-mirror.ps1             # 导表镜像干跑：待删除 / 待覆盖 / 孤儿 .meta 都应为 0
```

**为什么排第一**：这三道门禁上一次真实抓到过缺陷（一条 EditMode 用例暴露了"非导通格被凭空电击"
的产品 bug，根因在 `TileChainReactor.Propagate`）。而 EditMode 测试目前**没有任何自动化**——
`Window ▸ General ▸ Test Runner ▸ EditMode ▸ Run All` 是全手工的。建议：
一个 `Tools/ci.ps1` 串起三条门禁，再想办法把 EditMode 跑法写进 README / CI（Unity 命令行 `-runTests`）。

### ② 让"反应网"从"测试能证"变成"眼睛能看"

这是当前最大的**迭代摩擦**：反应只存在于配置里，主场景里能肉眼验证的只有火池那一条线。
三件小事一起做，收益很大：

1. **补 4 个种子图标**：`seed.icon_key` 指向 `Icons/Seed_Fire` / `Seed_Elec` / `Seed_Ice` / `Seed_Plant`，
   但 `Assets/Resources/Icons/` 下**只有一个 `sardline.png`** —— HUD 种子栏现在取不到图。
2. **补场景发生器地貌**：`Official` 的 `InitialSetup` 只刷了 6×4 火池。`element_duo_reaction` 的 6 条
   二级反应需要 **火池 / 电源 / 冰面 / 植物区** 两两相邻；现在除了火池那一列，其余根本无法触发。
   用笔刷刷几格，或往 `tile_initial.xlsx` 里加行（那张表是待填充基础设施，不是残留）。
3. **需要时打开 `[Reaction]` 追踪**（见 §1.4 末尾）——一行赋值就能把每次落地裁决打进 Console。

### ③ 接上多敌种刷怪（数据已备好，只差三处接线）

`enemy.xlsx` 已经有**精英怪**一行（6 血 / `contact_damage = 2`），但 `CombatDirector` 仍按
`Ids.Enemy`(=1) 生成全部敌人 —— 这一行数据目前是死的。要接上需要：

- `wave.xlsx` 加一列 `enemy_id`（并让 `WaveSpec` 透出）
- 放 `Assets/Resources/enemies/Enemy_2.prefab`（否则 `[Combat] 严重阻断` 会取消生成）
- 让 `EnemyBrainFactory.Create` 按 id 分流行为（现在一律 `ChaseBrain`）

> 顺带一提：`Assets/Resources/enemies/` 下现在**只有 `Enemy_1.prefab`**，
> 而敌人预制体的寻址规则是 `Resources/enemies/Enemy_<id>.prefab` —— 加怪种**必须先有预制体**。

### 备选（都不小，按兴趣挑）

- **`tile_state.is_obstacle` 接物理体**：陶砖标了 `is_obstacle = TRUE`，`TileStateSpec.IsObstacle` 也读得出来，
  但**全工程没有任何读取点** —— 既没挂 `Collider2D`，也没有决策看它，所以陶砖现在什么都挡不住。
  要接上得先让 `TilemapAdapter` 按 `IsObstacle` 增删 Collider，再让敌人决策认它。
- **结算期的掉落吸取 / 地貌残余消散**：表现层未做，现在结算期只是"等敌人清空"。
- **键位重绑**：`Attack / AltAttack / Plant / Aim` 走 `FindAction` 而非生成属性（刻意，见 `待办.md`），
  代价是它们进不了重绑 UI。
