# 新场景接线操作清单

一个可玩场景需要：`GameRoot` / `InputProvider` / `PlayerController` / `CombatRoot` / `TilemapAdapter` / 有地板的 Tilemap / 主相机 / Global Light 2D。
**禁止**：场景里放 `Canvas` / `EventSystem` / 第二个 `AudioListener`（UI 三件套由 `UIMgr` 从 `Assets/Resources/ui/` 自动创建）。
**敌人不用接线**：`CombatDirector` 运行时 `new GameObject("Enemy_…")` + `AddComponent<EnemyActor>()` 现场造（见 `Presentation/Actor/CombatDirector.cs`），场景里没有敌人预制体可拖。

> 参照实现：`Assets/Scenes/Sandboxes/Slice_PlayerFeel.unity`（玩家手感切片，无战斗）。`Slice_CombatSandbox.unity` 是战斗切片。

## 步骤 1：建场景

打开 `Assets/Settings/Scenes/URP2DSceneTemplate.unity` → `File ▸ Save As` 存成你的场景。它自带主相机（正交 Size 5、tag `MainCamera`）和 Global Light 2D。
自己建空场景则**必须手动加 Global Light 2D**，否则受光精灵全黑。

## 步骤 2：Tilemap

1. `GameObject ▸ 2D Object ▸ Tilemap ▸ Rectangular` → 得到 `Grid` 及其子物体 `Tilemap`
2. 子物体改名 `Ground`；复制两份，分别改名 `TileEffect`、`InitialSetup`
3. `Window ▸ 2D ▸ Tile Palette` 打开 `Assets/Resources/palettes/Demo_Palette.prefab`，在 **Ground** 层刷出地板（`Tile_Floor`），至少一格
4. 三层 `TilemapRenderer ▸ Sorting Order`：Ground = 0，InitialSetup = 1，TileEffect = 2

> `InitialSetup` 是关卡编辑层：用笔刷在此画开局的泥浆/火池/冰面，启动后被 `TilemapAdapter` 读走并 `SetActive(false)` 隐藏。**不画也行**，那么初始地块退回表驱动（`tile_initial`）；但该层对象要存在且接进 `TilemapAdapter.initialSetupTilemap`，否则 `LoadInitialSetupTiles` 直接返回 0，你画了也不生效且不报错。

> Sorting Order 只对地板贴图有意义；角色与格上特效的档位由 `RenderOrder` 统一频带（500–559，每世界单位 4 档）接管，**别靠 Z 轴或手填 Order 排序角色**。

## 步骤 3：GridView

新建根物体 `GridView`，挂 `TilemapAdapter`：

| 字段 | 值 |
| :-- | :-- |
| `groundTilemap` | 拖 Ground 的 Tilemap（**必接**，`IsWired` 只看它） |
| `effectTilemap` | 拖 TileEffect 的 Tilemap（**必接**，状态贴图盖这层） |
| `initialSetupTilemap` | 拖 InitialSetup 的 Tilemap（可选，见步骤 2 的说明） |
| `stateTiles` | Size 1；Element 0：`State = Mud`，`Tile = Assets/Resources/tiles/tilesets/demoTile/Tile_Mud.asset`（正式美术件；`Resources/tiles/Tile_Mud.asset` 是同名的纯色占位件，别拿错） |

> 功能件贴图可以留空 `Tile`：未配置的状态按 `tiles/Tile_<TileStateType 枚举名>` 约定懒加载（完整命名见 `Docs/美术装配指南.md`）。
> 三层**不能指向同一个 Tilemap**：`TilemapAdapter` 启动自检会报错并停用战斗内容。

## 步骤 4：BoundsArea（可选）

新建 `BoundsArea`：加 `BoxCollider2D` → **`Is Trigger` ✓** → `Size` = 可走区域（如 40×20）→ 位置放在区域中心。

## 步骤 5：玩家（Root-View 两层拓扑）

### 5.1 层级契约（硬性）

```text
Player                ← Root：物理真值 + 碰撞 + 组合根，带 Rigidbody2D / Collider2D / PlayerMotor / PlayerController
└── View              ← 纯视觉子节点，localPosition 必须是 (0,0,0)
    ├── SpriteRenderer
    ├── Animator      ← 可选，允许没有 Controller（白模期合法配置）
    └── ActorAnimationView
```

理由：受击抖动、后坐力、顿帧缩放、伪高度位移这些表现，将来只改 `View.transform.localPosition`。View 是 Root 的子节点 ⇒ 动它不碰刚体，物理阻挡与相机平滑跟踪都不受影响；反过来，把渲染器留在 Root 上，抖动就必然和物理位置打架。

### 5.2 建 Root 物体 `Player`

| 组件 | 字段 | 值 |
| :-- | :-- | :-- |
| Transform | Position | 出生点 |
| Rigidbody2D | Gravity Scale | 0 |
| | Constraints | Freeze Rotation Z ✓ |
| | **Interpolate** | **Interpolate**（相机跟踪用插值位置，Discrete 会抖） |
| | Collision Detection | Discrete（俯视角低速角色不需要 Continuous） |
| BoxCollider2D | Size | (0.7, 0.7)，非 Trigger |
| PlayerMotor | `body` | 留空（自取同物体上的 Rigidbody2D） |
| PlayerController | `motor` | 拖自己身上的 PlayerMotor |
| | `inputProvider` | 拖步骤 6 的 InputProvider |
| | `aimCamera` | 留空（默认取 `Camera.main`） |
| | `boundsArea` | 拖 BoundsArea 的 BoxCollider2D |
| | `animView` | 拖 5.3 建出来的 `ActorAnimationView` |

### 5.3 建子物体 `View`

右键 `Player ▸ Create Empty`，改名 `View`，**把 Transform 的 Position 与 Rotation 全部归零**（局部坐标必须 0，否则角色会整体偏移，且抖动特效的基准跟着歪）。

| 组件 | 字段 | 值 |
| :-- | :-- | :-- |
| SpriteRenderer | Sprite | 任意色块（如 `Assets/Resources/demo/Square.png`）；玩家切片用的是 `5ab94b21f0a9ff8479f9d84cc0bf2b42` 的色块 |
| | Color / Sorting Order | 随场景观感；Order 每帧会被 `RenderOrder.ActorOrder(Position.y)` 覆写，这里填的只是初始值 |
| Animator | Controller | **可留空**。留空即白模模式：所有动画调用是安全 no-op，零报错、零警告，`SpriteRenderer` 与 Y-Sort 照常工作 |
| ActorAnimationView | `animator` | 留空（`Awake` 自愈抓本节点）。同节点有 Animator 时不必拖 |
| | `spriteRenderer` | 留空（`Awake` 自愈抓本节点） |
| | `useFlipX` | **保持 ✗ 不勾**，原因见下 |

> **`SpriteRenderer` 必须挂在 `View` 上，不是 `Player` 根节点。** Y 排序每帧读的是 Root 的**物理体** `Position.y`，两处位置不一样；渲染器在 View 上，抖动才不会带歪排序，翻转也不会被 Root 的缩放符号叠第二次。
> `ActorAnimationView` 的 `animator` / `spriteRenderer` 自愈只用 `GetComponent`（**本节点**，不会往父级找）。所以 View 上没挂 `Animator` 又留空 `animator` 字段时，它会静默判定「无状态机」——这是合法配置，但别指望它自己去别处抓。

> 🔴 **`useFlipX` 必须保持关闭。** `ActorMotor.Facing` 已经把左右朝向落成 **Root 的 `localScale.x` 符号**（`移动Tests` 锁死了这条行为：朝左应翻成负缩放）。而 View 是 Root 的子节点，两条镜像作用在**同一根 x 轴**上：Root 翻 −1 再 `flipX` 镜像一次 = 完全抵消，**角色朝左反而显示成朝右**，不报错、不刷警告、测试也不会红。哪只角色改用状态机镜像，必须先停掉它 Root 上的缩放镜像，再打开这里。
> 反过来说：改代码不要动 `View.localScale`（它由 `PrimitiveSprites.Configure` 按精灵直径写，负号会被镜像语义吃掉）。

> 玩家数值不在这里拖：`ConfigModule.BindAssets` 读 `Assets/Resources/config/PlayerConfig.asset`（运动学参数在 `Resources/tuning/` 的调参 SO 里）。

## 步骤 6：InputProvider 与 GameRoot

各建一个空物体，分别挂 `InputProvider` 与 `GameRoot`，**没有需要拖的字段**。

## 步骤 7：CombatRoot 与 Fountain

| 对象 | 字段 | 值 |
| :-- | :-- | :-- |
| `CombatRoot` | `player` | 拖 PlayerController（必需） |
| | `gridView` | 拖 TilemapAdapter（必需） |
| | `ballRoot` / `actorRoot` | 可空（留空则球与敌人建在场景根下） |
| | `fountains` | 拖喷泉（可空） |
| | `enableWaves` | ✓ |
| `Fountain` | CircleCollider2D | **Is Trigger ✓**，Radius 3 |
| | `spawnInterval` | 1 |
| | `landingRadius` / `minLandingDistance` | 3 / 0.8 |

> `CombatRoot` 只接 `PlayerController`，**不接 `View` 与 `ActorAnimationView`**：玩家的动画/镜像由玩家侧自己翻译，世界侧只负责裁决死亡这类事实（`player.OnDeathTriggered()`）。接线时把表现细节塞回世界侧会让分层重新糊掉。
> 敌人的 `Enemy` -> `View` 两层由 `EnemyActor.Initialize → BuildVisuals` 运行时造，场景里看不到、也不需要接。`Enemy` 下还会多一个 `HpText` 兄弟节点（头顶耐久数字，故意挂 Root：它不该跟着 View 抖）。

## 步骤 8：Cinemachine（可选）

1. 主相机加 `Cinemachine Brain`（用 CM 菜单建 vcam 会自动加）
2. `GameObject ▸ Cinemachine ▸ 2D Camera`
3. vcam 设置：

| 字段 | 值 |
| :-- | :-- |
| `Follow` | 拖 Player（**拖 Root，别拖 View**） |
| `Look At` | 留空 |
| `Lens ▸ Orthographic Size` | 5 |
| `Body ▸ Framing Transposer ▸ Camera Distance` | 10 |
| `Body ▸ Framing Transposer ▸ Damping` | 0.15~0.3 |
| `Aim` | Do nothing |
| Brain ▸ Update Method | SmartUpdate |

4. （可选）限制相机不出图：vcam 加 `CinemachineConfiner` 扩展 → `Confine Mode = Confine2D`，`Bounding Shape 2D` 拖 `BoundsArea` 的 BoxCollider2D，`Confine Screen Edges ✓`

## 启动验收

进 Play，Console 应出现：

```
[Combat] 装配完成：格子 N 个（初始状态 0 个），球种 2 个，喷泉 M 个，敌人 启用
```

- 此时是菜单态（暂停），点 `BeginPanel` 的 `StartBtn` 开始
- WASD 移动、Shift 冲刺、左键水球、右键土球
- 走进喷泉圈等 1 秒拿水球；踩泥浆变慢；敌人追来接触掉血

### Root-View 分层专项验收

- [ ] Hierarchy 里 `Player` 下**只有** `View` 一个子物体，`View` 的 `localPosition = (0,0,0)`
- [ ] `Player` 根上**没有** `SpriteRenderer` / `Animator`
- [ ] `ActorAnimationView` 挂在 `View` 上，`PlayerController.animView` 指向它
- [ ] `useFlipX` 未勾选
- [ ] 移动、阻挡、冲刺手感不变；左右转身朝向正确（**不勾 `useFlipX` 时朝左应显示朝左**）
- [ ] 角色能从其他角色/NPC 前后正确穿插（Y-Sort 生效），暂停时排序也不乱
- [ ] Animator 无 Controller 时 Console **0 报错 0 警告**
- [ ] 按 1~4 打木桩：Hierarchy 里敌人是 `Enemy_x_y` -> `View`，伤害/减速/击退与碎裂死亡正常

## 最小排错表

| Console 文案 / 现象 | 修法 |
| :-- | :-- |
| `PlayerController 引用未接线` | 检查步骤 5.2 的 motor / inputProvider |
| `CombatRoot 引用未接线` | 检查步骤 7 的 player / gridView |
| `[Grid] 地板 Tilemap 上一个 tile 都没有` | 在 Ground 层刷地板 |
| `[Grid] TilemapAdapter 的 groundTilemap 与 effectTilemap 指向了同一层` | 分两层 |
| `[Grid] TilemapAdapter 的 initialSetupTilemap 与地板层／效果层指向了同一层` | InitialSetup 必须独立一层 |
| `[UI] 场景里已经有一份 EventSystem` | 删掉场景里的 Canvas / EventSystem |
| `[Ball] projectile 表里没有球种 X` | 跑 `Luban ▸ 表格数据导入` |
| 点鼠标没反应 | 主相机 tag 是否是 `MainCamera` |
| **角色朝左却显示朝右（或不翻转）** | `ActorAnimationView.useFlipX` 是否被勾上了（与 Root 缩放镜像抵消） |
| **Hierarchy 里 SpriteRenderer 在 `Player` 根上** | 移到 `View` 子节点；`PlayerController` 会自愈造一个 View，但旧渲染器不会被自动搬走 |
| **View 位置上偏/偏下，受击特效基准不对** | `View` 的 localPosition 未归零 |
| **相机跟着角色抖动一起动** | vcam 的 `Follow` 拖成了 `View`，应拖 Root |
| 玩家 / 地板发黑 | 加 Global Light 2D |
| 相机不动 | vcam 的 `Follow` 是否接上 |
| 相机抖 | Player 的 `Rigidbody2D.Interpolate` 是否是 Interpolate |
| 玩家被看不见的墙挡住 | `BoundsArea` 的 `Is Trigger` 是否勾上 |
