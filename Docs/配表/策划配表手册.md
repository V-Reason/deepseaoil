# 《策划配表手册》

> **改表入口**：`ConfigWorkspace/Data/*.xlsx` ｜ **生效方式**：Unity 菜单 **Luban ▸ 表格数据导入**
>
> 本版对应「温湿度伪拟真」退役后的**离散反应**口径。如果看到 `temp` / `wet` / `conductive` /
> `tile_effect` 这类字眼，说明你在看**旧文档**——那张表和那些列都已经不存在了。

---

## 一、配表铁律

1. **分工原则**：手感（移速、弹道抛物线、击退滑行、受击闪烁、敌人半径）去 Unity 调 SO 资产；
   **表里只填规则与结算数值**。表里删掉的边缘数值都在 SO 里，不能写回代码常量。
2. **符号禁区**：列表数组只用半角分号 **`;`**；标签掩码只用半角竖线 **`|`**。严禁中文标点与空格。
3. **不要手改表头四行**（`##var` / `##type` / `##group` / `##comment`）：字段名与类型是程序的契约，
   改名会让代码编译不过。列结构变动先与程序确认（**没有生成脚本可跑**，删列要在 Excel 里删干净、右侧不留孤立表头格）。
4. **枚举列选别名，别手打**：只有 `element_rule.source_tile` / `element_rule.result_tile` 与
   `element_duo_reaction.elem_a` / `elem_b` / `result_tile` 挂了单元格下拉框（列 = 16 个 `TileStateType` 别名），
   且这些格子填的是**中文别名**（`基础火池` / `普通泥浆`…）。**其余 7 张表一个下拉框都没有**，
   枚举格现状是：`element_rule.ball_type` 中文别名；`tile_state.id` 数字；`seed.id` 英文项名
   （`Fire` / `Elec` / `Ice` / `Plant`）、`seed.spawn_tile` 数字；`projectile.id` 英文项名（`Water` / `Earth`）；
   `wave.grant_seed` 英文项名。别名、英文项名、数字 Luban 都认。**统一成中文别名、并给其余表的枚举列补下拉框，
   是待办收尾工作**（见 `Docs/待办.md`）。
5. **改完必须导表**：Excel 不是运行时数据源，跑一次 **Luban ▸ 表格数据导入** 才生效。

---

## 二、核心表格（共 9 张）

### 1. `tile_state.xlsx`（地块状态属性 · 16 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 状态 ID，枚举 `TileStateType` 别名 | `空地` / `基础水` / `普通泥浆` / `导电区` … |
| `name` | 显示名（**只有诊断面板在读**，不在画面上显示） | 文字 |
| `duration` | 存活秒数，**`-1` = 永久**；到期回 `空地` | `-1` 或 `>0` |
| `slow_rate` | 踩在上面的移速倍率（**`1` = 不减速**，`<1` 减速，`>1` 加速） | `0 ~ 2` |
| `dot_damage` | 每秒持续伤害（`0` = 无） | 整数（列类型就是 `int`） |
| `is_obstacle` | 物理阻挡墙体（数据上只有 `陶砖` 为真） | `TRUE` / `FALSE` |
| `is_conductor` | **网格连锁导通体**（水 / 土 / 泥浆 / 稀泥 / 导电区为真） | `TRUE` / `FALSE` |

> ⚠️ **`dot_damage` 是整数列**（类型行就是 `int`，没有取整环节）：别填 `0.5`，
> 那会连导表都过不去。`Mathf.RoundToInt` 只作用在 `EnemyStats.ApplyDamage` 收到的伤害上，与这一列无关。
>
> ⚠️ **`is_obstacle` 只有数据、没有物理体**：`TileStateSpec.IsObstacle` 目前**全工程零读取点**，
> 所以陶砖能挡视线、能改决策**都没有实现**，"陶砖挡住敌人"是不成立的。
>
> ⚠️ **`is_conductor` 是电泛洪的唯一判据，且泛洪的起点自己也必须是导通体**。
> 把某状态标成"能通电"之前，先确认它两侧都能接上；`导电区` 之所以是 `TRUE`，正是因为
> 水砸电源生成它之后，连锁要从**它自己**开始传下去。

### 2. `element_rule.xlsx`（一级反应：原格 + 球 ➔ 新地貌 · 11 行）

> **匹配规则**：按 **`(原格状态, 球种)` 双键**查表，**唯一命中**。不是"自上而下首条命中"。
> ⚠️ **同组合出现两行，导表不报错**（`__tables__.xlsx` 的 `index` 只有 `id`，导表只查主键）：
> 是运行期 `ReactionResolver` 建表时打 `LogError`，**先到的那行生效、后到的被忽略**。

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 编号（仅作标识） | 唯一整数 |
| `source_tile` | **被砸之前**那一格的 `TileStateType` | 枚举别名 |
| `ball_type` | 投入的球种（`纯水` / `纯土`） | `BallType` 别名 |
| `result_tile` | 轰完变成什么（`空地` = 不改地形） | 枚举别名 |
| `impact_damage` | 瞬时伤害（打给**站在该格上**的敌人） | 整数 |
| `impact_knockback` | 击退距离（格） | `0 ~ 50` |
| `impact_stun` | 麻痹时间（秒） | `0 ~ 10` |
| `impact_radius` | 落地冲击的**波及半径**（格） | `1` = 只打中那一格；`>1` 为范围波及 |
| `trigger_chain` | 是否触发网格连锁（见下方判据） | `TRUE` / `FALSE` |

> 🔴 **`trigger_chain` 的判据是"结果地貌有没有连锁的方向"**，而不是"这次反应够不够炫"，
> 且**填 `TRUE` 不会凭空产生连锁** —— 程序只看结果地貌本身：
> 结果是 **`燎原火海`** 或 **可燃面（`基础植物区` / `带电荆棘`）** 时会起延烧（可燃格会烧穿成火海）；
> 结果是 **`is_conductor = TRUE` 的状态（会导电泛洪）** 时连锁才有去处。反之，**蒸汽 / 结冰 / 陶砖这类
> 既不可燃也不导通的产物填 `TRUE` 是空转**，只会让受击格白挨一次电击（`导电区` 是例外：
> 它自己就是导通体，所以 `基础电源 + 纯水 → 导电区` 那一行填 `TRUE` 是对的）。
>
> **兜底不走这张表**：表里没命中的组合同样有行为——**空地 + 水 → 基础水**、**空地 + 土 → 基础土**，
> 其余一律"地形不变、无伤害"。所以"扔水扔土能铺地面"不依赖这张表有没有写。

### 3. `element_duo_reaction.xlsx`（二级反应：两个发生器相邻触发 · 6 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 编号 | 唯一整数 |
| `elem_a` / `elem_b` | 相邻的两个**发生器**地貌（顺序无关，程序两种顺序都认） | 枚举别名 |
| `result_tile` | 激发出的地貌 | 枚举别名 |
| `impact_damage` | 瞬发伤害 | 整数 |
| `impact_knockback` | 击退距离（格） | `0 ~ 50` |
| `result_duration` | 结果的存续秒数 | `>0` |
| `effect_radius` | 波及半径（格，**以格为单位**） | `0 ~ 5` |
| `trigger_chain` | 是否继续连锁（判据同一级反应） | `TRUE` / `FALSE` |

> **这条表不会"两人站一起就触发"**：必须是两种**发生器**地貌成了四邻，且球砸中其中之一。
> 所以想验证二级反应，得先有火池 / 电源 / 冰面 / 植物区这些地貌（用种子播，或在场景里刷）。

### 4. `seed.xlsx`（种子基建 · 4 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 枚举 `SeedType`（当前格子里填的是英文项名 `Fire` / `Elec` / `Ice` / `Plant`） | `SeedType` 写法 |
| `name` | 显示名 —— **有消费者**（HUD 种子栏） | 文字 |
| `spawn_tile` | 播种后生成的地貌 | 枚举别名 |
| `icon_key` | 图标资源 Key | `Icons/Seed_Fire` 形式 |

> ⚠️ `icon_key` 指向的 4 个图标**当前在 `Assets/Resources/Icons/` 里还不存在**，HUD 取不到会走缺省。

### 5. `projectile.xlsx`（球种 · 2 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 球种 ID，枚举 `BallType`（当前格子里填的是英文项名 `Water` / `Earth`） | `BallType` 写法 |
| `name` | 显示名 | 文字 |

> **这张表只有 2 列**。抛物线与投掷距离**不在表里**——它们住在程序调参 SO
> `Assets/Resources/tuning/ThrowTuning.asset`（改表不会有任何反应）。
> "落地把格子切成什么" 也不再是这张表的列，**一律由 `element_rule` 决定**。
> **加新球种不是加一行就行**：`id` 被枚举 `BallType` 钉死，投掷入口也只绑了这两颗。

### 6. `enemy.xlsx`（敌人 · 2 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 编号（主键）。**同时是预制体寻址**：`Resources/enemies/Enemy_<id>.prefab` | 整数 |
| `name` | 显示名（**无消费者**） | 文字 |
| `max_speed` | 追击满速（单位/秒） | `0 ~ 50` |
| `hp` | 耐久（几下打碎） | `1 ~ 999` |
| `contact_damage` | **贴身一次**对玩家造成的伤害 | `0 ~ 999` |

> **半径 / 加速度 / 击退衰减 / 停止距离 / 脱战距离**已全部搬进
> `Assets/Resources/tuning/EnemyTuning.asset`（程序管辖，Play 时改即时生效、不用导表）。
> ⚠️ **第 2 行（精英怪）已经在表里，但刷不出精英怪**：还差三件事 —— 放
> `Assets/Resources/enemies/Enemy_2.prefab`（当前只有 `Enemy_1.prefab`）、让 `wave` 表有 `enemy_id`
> 取值口（`CombatDirector` 仍按 `Ids.Enemy`(=1) 的规格生成）、再让 `EnemyBrainFactory` 分流行为
> （现在一律追人）。表里那行现在只保证启动期 `GetEnemy(2)` 折得出来，不代表会被生成。

### 7. `player.xlsx`（玩家 · 1 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名（`name` **无消费者**） | `1` / 文字 |
| `max_hp` | 血量上限 | 当前 **3**（三颗心） |
| `contact_damage` | **零消费者**（接触伤害的权威已改成 `enemy.contact_damage`） | `float!#range=[0,9999]`，填 0 或超 9999 都会报错 |
| `invulnerable_duration` | 受击后无敌秒数 | `0 ~ 10` |
| `retry_delay` | 打空后到重来的停顿（秒） | `0 ~ 60` |
| `attack_interval` | 两次攻击最短间隔（秒） | `0.01 ~ 10` |
| `knockback_impulse` | 受击被推开的冲量 | `0 ~ 100` |
| `knockback_speed_limit` | 受击期间速度上限（**程序当冲量上限夹**，与冲量填同数最直观） | `0 ~ 100` |
| `contact_radius` | 判定"敌人贴上了"的圆心距（世界单位） | `0.05 ~ 10` |
| `water_capacity` / `water_start` | 水弹药上限 / 开局量 | 整数 |
| `earth_capacity` / `earth_start` | 土弹药上限 / 开局量 | 整数 |
| `life_heal_interval` | 神泉回血所需静止秒数 | `0.1 ~ 60` |

> 玩家的**移动**数值不在这张表里（走 `Resources/config/PlayerConfig.asset` 那份 SO）。
> 程序固定取 `id = 1`，改 `id` 会让代码取不到行。

### 8. `wave.xlsx`（波次 · 3 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名 | 整数 / 文字 |
| `prep_time` | **备战时长**（秒，可播种子） | `0 ~ 60` |
| `battle_time` | **战斗时长**（秒） | `0 ~ 300` |
| `settle_time` | **结算时长**（秒，等敌人清空） | `0 ~ 60` |
| `enemies_per_wave` | 敌人数 | `1 ~ 100` |
| `spawn_interval` | 同波内两只之间的间隔（秒） | `0.01 ~ 10` |
| `spawn_radius` | 出生环半径（世界单位，以玩家为圆心） | `0.5 ~ 50` |
| `grant_seed` | **备战期配给的种子**（枚举 `SeedType`，当前填英文项名 `Fire` / `Elec` / `Ice`） | `SeedType` 写法 |

> 与旧版不同：现在是 **备战 → 战斗 → 结算** 三段式，不再是 `initial_delay` / `respawn_delay`。
> **`wave` 会遍历全表**（不再只读 `id = 1`），三行会依次推进并循环。

### 9. `tile_initial.xlsx`（关卡初始格子状态 · **当前 0 行**）

| 列名 | 含义 |
| :-- | :-- |
| `id` | 编号 |
| `cell_x` / `cell_y` | 格子坐标 |
| `state_id` | 该格的初始 `TileStateType` |

> **当前 0 行不是残留，是待填充基础设施**。开局地貌现在靠在场景里用笔刷画
> （`Official.unity` 的 `InitialSetup` 图层已有 24 格基础火池，是 6×4 块），或靠玩家投掷 / 播种自己铺。
> 想改用表驱动，直接加行即可。

## 三、改表 3 步防坑检查

1. **查符号**：没有用中文分号 `；`。注意：**当前 9 张表没有一列是列表 / 数组 / 标签掩码**
   （也没有 `#ref=` 外键列），所以半角分号与竖线的规则暂时无处可犯，加那类列时才适用。
2. **查主键**：**主键一律是 `id`，导表只查它有没有重复**。
   `element_rule` 的 `(source_tile, ball_type)` 组合重复**导表不报错**，只在运行期报 `LogError`
   （见 §二.2）；`trigger_chain = TRUE` 的行，其结果地貌**必须可燃或是导通体**（见 §二.2 判据）。
3. **查导表**：Unity 中点击 **Luban ▸ 表格数据导入**，Console 无红字报错。
   导表用 `--strict`，**类型非法 / `#range` 越界 / 枚举值非法 / 主键重复 / 缺列都会当场报错**。
