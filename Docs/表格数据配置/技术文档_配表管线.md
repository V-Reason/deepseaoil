# 技术文档：配表管线

面向**程序**。策划操作见 [`策划手册_数据表填写.md`](策划手册_数据表填写.md)。

## 1. 准入

| 项 | 要求 |
| :-- | :-- |
| Unity | 2022.3.62f3c1（URP 14.0.12） |
| .NET 运行时 | `Microsoft.NETCore.App` ≥ 8.0.0（**不需要 SDK**）。`ConfigWorkspace/Tools/Luban/Luban.runtimeconfig.json` 声明 `tfm = net8.0`。注：`LubanImport.DescribeLaunchFailure` 的提示文案写的是「请安装 .NET SDK 8+ 后重启 Unity」，与"不需要 SDK"不一致（**待核对**） |
| Git LFS | 拉 `ConfigWorkspace/Tools/Luban/` 的 `*.dll` / `*.exe` 之前必须装 |
| Luban 工具 | 随仓库交付，入口 `ConfigWorkspace/Tools/Luban/Luban.dll`。导表进程的工作目录就是 `ConfigWorkspace`，所以命令行一律写相对路径 `Tools/Luban/Luban.dll` —— 工程根下**没有** `Tools/` 那个目录 |
| Unity 侧运行库 | `Assets/Luban.Runtime/`，**本地拷贝，不走 UPM** |

🔴 **不要装 Luban 的 UPM 包**：本地拷贝与 UPM 包的 asmdef 都叫 `Luban.Runtime`，撞名报 `Assembly with name 'Luban.Runtime' already exists`，**整个工程所有程序集都编译不出来**。

## 2. 链路

```text
ConfigWorkspace/Data/*.xlsx            源表；登记在 __tables__.xlsx
        ↓  dotnet Tools/Luban/Luban.dll --conf luban.conf -t client --strict
             -c cs-simple-json -d json
             -x outputCodeDir=output/code -x outputDataDir=output/data
             -x pathValidator.rootDir=<工程>/Assets
           （工作目录 = ConfigWorkspace；参数表见 LubanProject.BuildExportCommand）
ConfigWorkspace/output/{code,data}     暂存区（gitignore）
        ↓  退出码 == 0 才发布：镜像拷贝
Assets/Scripts/Generated/Config/  +  Assets/StreamingAssets/Luban/
        ↓  cfg.Tables 由 TablesHolder 构造
DeepseaOil.Data.ConfigModule           运行期唯一的**数值**入口（查询面是 GetXxx ＋ *Spec）
```

🔴 **发布闸门是退出码，不是 Luban 的行为**——Luban 校验失败也会写暂存区。

⚠️ **资源路径列（如 `icon`）的校验盲区**：`#path=unity` 只校验文件在 `Assets/` 下**存在**，不校验它在 `Assets/Resources/` 下，而运行期 `Resources.LoadAsync` 只能加载后者。填错地方**导表通过、运行期才失败**。当前 8 张表**一个 `#path=unity` 列都没有**，这类列也没有任何运行期消费者（从前只有 `Presentation/Diagnostics/ConfigLoader.cs` 打印它、`Data层Tests` 断言它像个资源路径），所以眼下表现为"没人发现"；一旦接 UI 取图，这条盲区立刻成立。

**不在表里的数值（别去表里找）**：水球掉落物的 5 个数（飞行时长 / 弧高 / 飞向玩家的速度 / 判定距离 / 领取数量）来自 SO `Assets/Resources/tuning/DropTuning.asset`（`DropSpec` / `DropTuning` 折算）；`DropType` 是 `Assets/Scripts/Data/Config/DropType.cs` 里的 C# 枚举，不是 `__enums__.xlsx` 里的表枚举。改掉落物手感改 SO，不用导表。

**枚举（`__enums__.xlsx`）**：`dso.Quality`（**零消费者的遗留**，其表已下架）、`dso.BallType`（`Water` 水 / `Earth` 土）、`dso.TileStateType`（`Normal` 常规 / `Mud` 泥浆）。枚举列的数据格填**别名**（中文），如 `水` / `泥浆`。

**加表后要同步一处手写清单**：`Assets/Scripts/Data/Config/TablesMeta.cs` 的 `Names` 数组（给 `DataMetrics.TableCount` 与 `StartupValidator` 用，当前 8 条）。加表 / 加枚举会新增生成物文件，而生成物目录本来就不再被测试逐个登记（原先那条文件名白名单已删：加一张表就要同步一次，纯摩擦）。

### 3.1.1 🔴 实测坑：`##type` 里的 `!` 是"**不许是默认值**"，不是"必填"

`!` 要求该列**不能等于类型的默认值**（数字是 `0`、字符串是空）：

| 写法 | 填 `0` 会怎样 | 该写什么 |
| :-- | :-- | :-- |
| `float!#range=[0,10]` | **校验失败**：`…field:0 (来自文件:Sheet1@…xlsx) 是一个默认值` | 可填 0 的列去掉 `!`：`float#range=[0,10]` |
| `float!#range=[0.05,5]` | 通过（0 不在范围里，会先被范围规则拦下） | 保持 |

**判据**：这一列的合法取值里包含 `0` 时不要加 `!`。（`tile_state` 的"常规"行 `duration` / `enter_damage` / `enter_knockback` 天然是 0，四列都带 `!` 会直接导表失败。）

### 3.2 改输入输出路径

路径推算全部集中在 `Assets/Editor/LubanProject.cs`，无硬编码盘符。**必须成套改**，漏一处会出现"导成功了但工程没变"。

| 要改什么 | 改哪里 |
| :-- | :-- |
| 源表目录 | `luban.conf` 的 `dataDir`；新建表还要加到 `schemaFiles` |
| 生成代码 / 数据目录 | `BuildExportCommand` 里 `-x outputCodeDir=` / `-x outputDataDir=` —— 必须指向暂存区 |
| 发布目录 | `LubanProject.OutputCodeDir` / `OutputDataDir` —— 与上面两行配对 |
| 暂存区 | `LubanProject.StageCodeDir` / `StageDataDir` —— 改了它，两个 `-x` 要一起改 |
| 日志目录 | `LubanProject.LogsDir`（gitignore） |
| `#path=unity` 的基准 | `LubanProject.PathValidatorRoot`（现为 `Assets`） |

写绝对路径也能跑通，但会锁死本机布局，且路径不存在时报原生英文错 `Could not find a part of the path …` —— 一律用相对路径。

### 3.3 改代码（不用导表）

| 文件 | 影响 |
| :-- | :-- |
| `Assets/Scripts/Data/Config/` | 运行期怎么读 JSON、怎么暴露查询：`ConfigModule`（唯一入口，含只读逃生舱 `Tables`）→ `Spec/*Spec`（表行 → 纯结构体的折算点）→ 调用方；`TablesMeta.Names` 是手写的表清单 |

| `Assets/Resources/tuning/{ThrowTuning,DropTuning,VisualPalette}.asset` | 上表几份观感资产，**必须随仓库发布**（见下） |
| `Assets/Scripts/Presentation/Diagnostics/ConfigLoader.cs` | 链路自检示例（可选，删掉不影响导表） |
| `Assets/Luban.Runtime/` | 运行期反序列化实现 |
| `Assets/Editor/*.cs` | 导表工具本身：`LubanProject`（路径推算 ＋ 命令行）、`LubanImport`（暂存 ＋ 镜像拷贝 ＋ 日志）、`LubanMenu`（菜单入口）、`LubanAutoTrigger`，改完下次导表生效 |

**观感 SO 必须随仓库发布**：`Assets/Resources/tuning/ThrowTuning.asset`（键 `tuning/ThrowTuning`）与 `DropTuning.asset`，都走 `AssetModule` 的同步窄路。资产缺失时 `ThrowTuning.LoadOrDefault()` / `DropTuning.LoadOrDefault()` 会退化成「一份字段默认值的实例」，投掷观感与冲量、掉落物抛物线手感随之失效 —— 这是**安全网，不是正常路径**：真丢了资产，`AssetModule` 会先记一条加载失败（计入 `DataMetrics`），`LoadOrDefault` 再打一条 Warning，两条同时出现就说明资产没进仓库。

## 4. 禁区与排障

| 注意 | 违反了会怎样 |
| :-- | :-- |
| **Luban 清空它的两个输出目录**：`-x` 指向的目录先整体清空再重写，不区分谁生成的 | 往 `ConfigWorkspace/output/` 放手写文件，下次导表直接消失 |
| **发布目录由镜像拷贝清理**：暂存区没有的文件会被删除（**`.meta` 例外保留**） | 往两个生成目录放手写文件必丢 |
| **不在生成类里写逻辑**：`Generated/Config/` 每次导入整体重写 | 手写的字段、方法、注释全丢。生成类都是 `partial`，要扩展就另建文件 |
| 调用参数必须带 `--strict` | 校验失败不改变退出码，闸门失效，坏数据被当成功发布 |
| 两个 `-x` 只能指向 `ConfigWorkspace/output/` | Luban 的写盘发生在校验之后；直接指向 `Assets/` 时一次失败导入当场毁掉整个生成目录 |
| 必须走「暂存区 → 退出码 0 → 镜像拷贝」 | 少了这层，校验失败的中间态直接进工程 |
| 仅校验模式要同时带 `-f` 与 `-x outputSaver=null` | 只带 `-f` 不保证零写入 |
| 工作目录必须是 `ConfigWorkspace` | conf 内的相对路径解析失败，报「表输入路径未找到」 |
| **删列 / 改字段名必须先通知程序**（加列、加表免通知） | 引用该字段的代码当场编译报错，策划无法自行修复 |
| `Assets/` 下所有文件与目录的 `.meta` 必须提交 | Unity 靠 GUID 维持引用，漏提交会让队友那边引用全断 |
| 新建表必须登记进 `__tables__.xlsx` | 表被静默忽略，导表不报错，白做 |
| 一格多值不支持：`list` / `array` 单元格不按分隔符拆，`map` 写法未通过验证 | 被当成一个元素，数据静默变形 |
| 怀疑路径推算错误 | 跑菜单 **Luban ▸ 路径自检（不导入）**：打印全部推算路径、两条未转义命令行、当前锁文件清单 |
