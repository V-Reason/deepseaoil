# 策划手册：数据表填写

## 1. 导一次表

| 步 | 动作 |
| :-- | :-- |
| 1 | `Git` 拉取最新改动 |
| 2 | 改 `ConfigWorkspace/Data/` 下的表格（表头 4 行见 §2） |
| 3 | **保存** |
| 4 | **保存并关闭 Excel**（Excel 开着也能导成功，读的是磁盘上已保存的那一版 —— 真正的风险是"改了没保存就导入，静默用旧数据"。预检会检测 `~$xxx.xlsx` 占用标记并拦下，只报告、不替你删） |

## 2. 怎么调表

工作路径：

![p3](image\p3.png)

### 表头四行

| 行 | A1 列 | 非 A1 列填什么 | 例 |
| :-- | :-- | :-- | :-- |
| 1 | `##var` | 程序字段名，**只允许小写英文和下划线** | `atk_speed` |
| 2 | `##type` | 数据类型，见下表 | `float` |
| 3 | `##group` | 分组，目前一律填 `c`（client 客户端） | `c` |
| 4 | `##comment` | 中文注释，会写成程序里的注释 | `攻速` |
| 5 起 | 空 | **数据从这里开始，第 1 列不填** | `1.2` |

![p4](image\p4.png)

### 数据类型（第 2 行）

| 我要什么 | 写什么 | 留空会怎样 |
| :-- | :-- | :-- |
| 整数（32 位 / 64 位）/ 小数 / 文字 / 是否 | `int` / `long` / `float` / `string` / `bool` | 0 / 0 / 0 / 空 / 否 |
| 必须填 | `int!` `float!`（加叹号） | 报错 |
| 限范围 | `int#range=[1,100]`；`[1,]` 表示 1 到无穷 | 报错 |
| 引用他表（外键） | `int#ref=dso.TbEnemy` | 报错 |
| 引用可空 | `int#ref=dso.TbEnemy?` | 不报 |
| 限定取值 | `int#(set=1,2,3)`（**当前 9 张表没有一列用过**） | 报错 |
| 资源路径 | `string#path=unity`，填**相对 `Assets`** 的路径 | 不报 |
| 枚举 | 直接写枚举全名，如 `TileStateType` / `BallType` / `SeedType` | 报错 |

- 限制符写在**类型行**，不写数据格；多值必须**括号 + 逗号**，用 `;` 直接报错。
- ⚠️ `!` 的含义是"**不许是默认值**"（数字的默认值是 `0`），不是"必填"：这一列的合法取值里包含 `0` 时**不要加 `!`**。详见《技术文档_配表管线》§3.1.1。
- 🔴 程序**只能加载 `Assets/Resources/` 下**的资源。导表期只校验"文件在 `Assets/` 下存在"，不校验它在 `Resources/` 下——填了别处的路径**导表不报错**，将来接上取图的代码就是运行期加载失败。资源一律放 `Assets/Resources/` 下再填。

### 加表

表格文件自己建，但**必须登记**：在 `ConfigWorkspace/Data/__tables__.xlsx` 加一行。

| 列 | 填什么 | 例 |
| :-- | :-- | :-- |
| `full_name` | 模块名 + `Tb` + 记录名 | `dso.TbEnemy` |
| `value_type` | 记录类名 | `Enemy` |
| `read_schema_from_file` | 填 `1`：字段定义从这张表自己的表头读 | `1` |
| `input` | 表格文件名 | `enemy.xlsx` |
| `index` | 主键字段 | `id` |
| `group` | 填 `c`（留空 = 属于所有分组） | `c` |
| `output` | 生成的数据文件名；**留空则默认 `<模块>_<表名>`** | `dso_tbenemy` |

> 当前 9 张表的 `output` 全部留空，一律走默认。上表之外还有 `mode` / `comment` / `tags` 三列：`mode` 与 `tags` 留空即可，`comment` 建议填一句中文说明。
>
> **主键一律是 `id`**（当前 9 张表的 `index` 列全部填 `id`）。

![p5](image\p5.png)

### 加列

**可以插在任意位置**，包括两个已有字段之间。插入一列 → 填齐 4 行表头 → 逐行补数据格（留空可以，但**数字格留空会变成 `0`**）→ 保存 → 关 Excel → 导表。

> ⚠️ **删列要在 Excel 里删干净**：表头是 Luban 的 schema 来源，手工删列时若在右侧留下孤立的表头格，
> 导表会报"字段 X 类型 Y 非法"这种幽灵错误。列结构变动先与程序确认。

![p6](image\p6.png)

### 登记枚举

在 `ConfigWorkspace/Data/__enums__.xlsx`：`full_name` 写完整枚举名（如 `dso.BallType`），**每个枚举项占一行**。

![p7](image\p7.png)

**枚举列的数据怎么填**：`dso.TileStateType` / `dso.BallType` / `dso.SeedType` 三类列在 Excel 里已挂
**数据验证下拉框**，**点开下拉框选中文别名**即可，不用背英文项名和数字：

| 枚举 | 下拉框里选什么 | 当前可选值 |
| :-- | :-- | :-- |
| `dso.TileStateType`（地块状态） | **中文别名** | `空地` · `基础水` · `基础土` · `基础火池` · `基础冰面` · `基础电源` · `基础植物区` · `普通泥浆` · `稀泥` · `陶砖` · `结冰` · `蒸汽` · `导电区` · `燎原火海` · `带电荆棘` · `霜冻冰刺` |
| `dso.BallType`（球种） | **中文别名** | `纯水` / `纯土` |
| `dso.SeedType`（种子） | **中文别名** | `火种子` / `电种子` / `冰种子` / `植物种子` |

> 别名、英文项名（`Water` / `Fire`…）、数字三种写法 Luban 都认，但**仓里数据一律用中文别名**，别混用。
> 下拉列表直接来自枚举定义，`无状态` / `空种子` 这类占位项不在列表里 —— 它们不是可填的地块 / 种子。

### 战斗相关的九张表

填写口径：**只改数据格，不要动这四行表头**（字段名 / 类型是程序的契约，改字段名会让代码编译不过）。
逐列的"有没有消费者"写在每张表下 —— **列了但代码里没人读的列，改它不会有任何效果**。

先给一句汇总：`enemy.name` / `player.name` / `wave.name` 都**无消费者**（改它们画面上不会出现任何字）；
`seed.name` **有**消费者（HUD 种子栏在读）；`player.contact_damage` 已零消费者（权威改到了
`enemy.contact_damage`）；`tile_initial` 整张表 0 行。`enemy` / `player` 两张表程序只读 `id = 1`
（`ConfigModule.Ids` 写死），`wave` 已改成**遍历全表**。

#### `projectile.xlsx` — 球种（2 行：水球 / 土球）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 球种 ID（枚举 `dso.BallType`） | `纯水` / `纯土` |
| `name` | 显示名 | 文字 |

> **这张表只有 2 列。** 抛物线与投掷距离（`flight_duration` / `max_height` / `max_throw_distance` /
> `min_throw_distance`）**已全部搬进程序调参 SO** `Assets/Resources/tuning/ThrowTuning.asset`
> —— 改表不会有任何反应，要调抛物线请找程序改那份 SO。
> **"落地把格子切成什么"也不再是这张表的列**：一律由 `element_rule.xlsx` 决定。
> **球本身不造成任何伤害**：伤害 / 击退 / 麻痹全部来自 `element_rule` 表。
> ⚠️ **加新球种不是加一行就行**：`id` 被枚举 `dso.BallType` 钉死（现在只有两颗），投掷入口也只绑了这两个键。

#### `element_rule.xlsx` — 一级反应：原格 ＋ 球 ➔ 新地貌（11 行）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 编号（仅作标识，须唯一） | 整数 |
| `source_tile` | **被砸之前**那一格的状态 | `TileStateType` 别名 |
| `ball_type` | 投入的球种 | `纯水` / `纯土` |
| `result_tile` | 轰完变成什么（`空地` = 不改地形） | `TileStateType` 别名 |
| `impact_damage` | 瞬时伤害（打给**站在该格上**的敌人） | 整数 |
| `impact_knockback` | 击退距离（格） | `0 ~ 50` |
| `impact_stun` | 麻痹时间（秒） | `0 ~ 10` |
| `impact_radius` | 落地冲击的**波及半径**（格） | `1` = 只打中那一格；`>1` 为范围波及 |
| `trigger_chain` | 是否触发网格连锁 | `TRUE` / `FALSE` |

> 🔴 **`(source_tile, ball_type)` 组合必须唯一** —— 程序按这个双键建哈希表查表，重复组合导表会报错。
> 匹配规则不是"自上而下首条命中"，是**唯一键查表**。
>
> 🔴 **`trigger_chain` 的判据是"结果地貌有没有连锁的方向"**：只有结果是 `燎原火海`（可燃）
> 或 `is_conductor = TRUE` 的状态（会导电泛洪）时连锁才有去处。**蒸汽 / 结冰 / 陶砖这类既不可燃
> 也不导通的结果填 `TRUE`，只会让受击格凭空多挨一次电击**。
>
> **兜底不走这张表**：表里没命中的组合同样有行为 —— **空地＋水 → 基础水**、**空地＋土 → 基础土**，
> 其余一律"地形不变、无伤害"。所以"扔水扔土就能铺地面"不依赖这张表。

#### `element_duo_reaction.xlsx` — 二级反应（6 行）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 编号 | 整数 |
| `elem_a` / `elem_b` | 相邻的两个**发生器**地貌（顺序无关） | `TileStateType` 别名 |
| `result_tile` | 激发出的地貌 | `TileStateType` 别名 |
| `impact_damage` | 瞬发伤害 | 整数 |
| `impact_knockback` | 击退距离（格） | `0 ~ 50` |
| `result_duration` | 结果的存续秒数 | `>0` |
| `effect_radius` | 波及半径（**以格为单位**） | `0 ~ 5` |
| `trigger_chain` | 是否继续连锁（判据同 `element_rule`） | `TRUE` / `FALSE` |

> **必须是两种"发生器"地貌成了四邻、且球砸中其中之一**才会触发，不是"两人站一起就发生"。
> 想验证二级反应，得先有火池 / 电源 / 冰面 / 植物区这些地貌（用种子播，或在场景里刷）。

#### `tile_state.xlsx` — 地块状态属性（16 行）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 状态 ID（枚举 `dso.TileStateType`，填**中文别名**） | 见 §2 枚举表 |
| `name` | 显示名（**当前无消费者**） | 文字 |
| `duration` | 存活秒数，**`-1` = 永久**；到期回空地 | `-1` 或 `>0` |
| `slow_rate` | 踩在上面的移速倍率（**`1` = 不减速**，`<1` 减速，`>1` 加速） | `0 ~ 2` |
| `dot_damage` | **每秒**持续伤害（`0` = 无） | 整数，**别填 0.5** |
| `is_obstacle` | 物理阻挡墙体（当前只有 `陶砖` 为真） | `TRUE` / `FALSE` |
| `is_conductor` | **网格连锁导通体**（`普通泥浆`/`稀泥`/`基础水`/`基础土`/`导电区` 为真） | `TRUE` / `FALSE` |

> ⚠️ 旧的 `enter_damage` / `enter_knockback` 两列**已退役**：伤害与击退改成由 `element_rule`
> 在**这次转换**发生的那一刻结算，本表只管"地貌自身持续施加什么"。
> ⚠️ **`dot_damage` 会取整**：程序走 `Mathf.RoundToInt`，填 `0.5` 会被舍成 **0** 而**静默无效**。
> 要么保持 ≥1 的整数，要么先让程序支持小数耐久。
> ⚠️ **`is_obstacle` 只有数据、没有物理体**：程序读得出来，但还没有人按它挂 `Collider2D`，
> 所以陶砖能挡视线、能改决策，**敌人不会真的被墙挡住**。
> ⚠️ **`is_conductor` 是电泛洪的唯一判据，且泛洪的起点自己也必须是导通体**。`导电区` 之所以
> 是 `TRUE`，正是因为水砸电源生成它之后，连锁要从**它自己**开始传下去。

#### `seed.xlsx` — 种子基建（4 行）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 枚举 `dso.SeedType` | `火种子` / `电种子` / `冰种子` / `植物种子` |
| `name` | 显示名 —— **有消费者**（HUD 种子栏） | 文字 |
| `spawn_tile` | 播种后生成的地貌 | `TileStateType` 别名 |
| `icon_key` | 图标资源 Key | `Icons/Seed_Fire` 形式 |

> ⚠️ `icon_key` 指的 4 个图标**当前在 `Assets/Resources/Icons/` 里还不存在**，HUD 取不到会走缺省。

#### `enemy.xlsx` — 敌人（2 行：普通怪 / 精英怪）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 编号（主键）。**同时是预制体寻址**：`Resources/enemies/Enemy_<id>.prefab` | 整数 |
| `name` | 显示名 —— **当前无消费者** | 文字 |
| `max_speed` | 追击满速（单位/秒） | `0 ~ 50` |
| `hp` | 耐久（几下打碎） | `1 ~ 999` |
| `contact_damage` | **贴身一次**对玩家造成的伤害 | `0 ~ 999` |

> **半径 / 加速度 / 击退衰减 / 停止距离 / 脱战距离已按《最新表格与SO规范》搬进调参 SO**
> `Assets/Resources/tuning/EnemyTuning.asset`（程序管辖，Play Mode 改即时生效、不用导表）
> —— 要调"被撞多远滑多久""贴多近停下""多远脱战""身体多大"，请找程序改那份 SO，**改表不会有反应**。
> ⚠️ **加第二种敌人是三件事**：表加一行 ＋ 放 `Enemy_<id>.prefab` ＋ 让 `EnemyBrainFactory`

#### `player.xlsx` — 玩家（1 行）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名（`name` **当前无消费者**） | `1` / 文字 |
| `max_hp` | 血量上限 | `1 ~ 99999`（当前 **3** = 三颗心） |
| `contact_damage` | **零消费者**（接触伤害权威已改到 `enemy.contact_damage`） | 随便 |
| `invulnerable_duration` | 受击后的无敌时长（秒） | `0 ~ 10` |
| `retry_delay` | 打空后到重来之间的停顿（秒） | `0 ~ 60` |
| `attack_interval` | 两次攻击之间的最短间隔（秒） | `0.01 ~ 10` |
| `knockback_impulse` | 受击被推开的冲量 | `0 ~ 100` |
| `knockback_speed_limit` | 受击期间的速度上限 —— **程序把它当作冲量的上限来夹**，所以填得比冲量小就推不满、填大了等于不限；**与冲量填同一个数**最直观 | `0 ~ 100` |
| `contact_radius` | 判定"敌人贴上了"的圆心距（世界单位） | `0.05 ~ 10` |
| `water_capacity` / `water_start` | 水弹药上限 / 开局量 | `0 ~ 99` |

> 玩家的**移动**数值不在这张表里（走 `Assets/Resources/config/PlayerConfig.asset` 那份 SO）。

#### `wave.xlsx` — 波次（3 行）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名 | 整数 / 文字 |
| `prep_time` | **备战时长**（秒，可播种子） | `0 ~ 60` |
| `battle_time` | **战斗时长**（秒） | `0 ~ 300` |
| `settle_time` | **结算时长**（秒，等敌人清空） | `0 ~ 60` |
| `enemies_per_wave` | 每波敌人数 | `1 ~ 100` |
| `spawn_interval` | 同波内两只之间的间隔（秒） | `0.01 ~ 10` |
| `spawn_radius` | 出生环半径（世界单位，以玩家为圆心） | `0.5 ~ 50` |
| `grant_seed` | **备战期配给的种子**（枚举 `dso.SeedType`） | `火种子` / `电种子` / `冰种子` / `植物种子` |

> 与旧版不同：现在是 **备战 → 战斗 → 结算** 三段式，不再有 `initial_delay` / `respawn_delay`。
> **`wave` 会遍历全表**（不再只读 `id = 1`），三行依次推进、跑完循环回第一行。

#### `tile_initial.xlsx` — 关卡初始格子状态（**当前 0 行**）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 编号（主键，随便给不重复的整数） | 整数 |
| `cell_x` / `cell_y` | 格子坐标（**必填**） | 整数 |
| `state_id` | 初始状态 | `TileStateType` 别名 |

> **这张表现在是兜底的（0 行）**：初始地块的权威来源是场景 `Grid/InitialSetup` 笔刷层
> （`TilemapAdapter.LoadInitialSetupTiles` 先读它，`EmptyTest` 里已刷了 9 格）；只有"场景里一个
> 初始地块都没刷"时，程序才回头读这张表。读不到行就什么也不做，也不报错。
> 填了行也会生效 —— 但只作用于"当前场景里真的铺了地板的格"；没地板的坐标被忽略。
> **关卡布局请去场景里刷**（见《美术装配指南》第三层结构），别在这张表里手填坐标：
> 改一张图要填几百行、且没有可视化预览。
> 当前没有「关卡」维度：所有行都作用于当前场景；关卡系统立项后再加 `level` 列。

## 3. 报错对照

报错原文格式是 `记录 <表全名>[<主键>].<字段>:<填的值> (来自文件:<sheet>@<xlsx 路径>) <原因>` —— **`[]` 里就是那一行的主键**，按它去表里找行。一张表的多个错误会一次全列出来（不用改一个导一次）。

| 报错片段 | 我该改哪一格 |
| :-- | :-- |
