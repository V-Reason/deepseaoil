# 策划手册：数据表填写

## 1. 导一次表

| 步 | 动作 |
| :-- | :-- |
| 1 | `Git` 拉取最新改动 |
| 2 | 改 `ConfigWorkspace/Data/` 下的表格（表头 4 行见 §2） |
| 3 | **保存** |
| 4 | **保存并关闭 Excel**（Excel 开着也能导成功，读的是磁盘上已保存的那一版 —— 真正的风险是"改了没保存就导入，静默用旧数据"。预检会检测 `~$xxx.xlsx` 占用标记并拦下，只报告、不替你删） |
| 5 | 切回 Unity，按 <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd>（菜单 `Luban ▸ 表格数据导入`；<kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>K</kbd> 是仅校验，只报错不写盘） |
| 6 | `Git` 提交：表格与 `Assets/Scripts/Generated/Config/`、`Assets/StreamingAssets/Luban/` 下的生成物一起提交 |

**导入失败不改动工程里任何文件，反复重试是安全的。** 报错照 §3 改。

## 2. 怎么调表

工作路径：

![p3](image\p3.png)

### 表头四行

| 行 | A1 列 | 非 A1 列填什么 | 例 |
| :-- | :-- | :-- | :-- |
| 1 | `##var` | 程序字段名，**只允许小写英文和下划线** | `atk_speed` |
| 2 | `##type` | 数据类型，见下表 | `float` |
| 3 | `##group` | 分组，目前一律填 `c`（client 客户端） | `c` |
| 4 | `##comment` | 中文注释，会写成程序里的注释 | `攻速` |
| 5 起 | 空 | **数据从这里开始，第 1 列不填** | `1.2` |

![p4](image\p4.png)

### 数据类型（第 2 行）

| 我要什么 | 写什么 | 留空会怎样 |
| :-- | :-- | :-- |
| 整数（32 位 / 64 位）/ 小数 / 文字 / 是否 | `int` / `long` / `float` / `string` / `bool` | 0 / 0 / 0 / 空 / 否 |
| 必须填 | `int!` `float!`（加叹号） | 报错 |
| 限范围 | `int#range=[1,100]`；`[1,]` 表示 1 到无穷 | 报错 |
| 引用他表（外键） | `int#ref=dso.TbEnemy` | 报错 |
| 引用可空 | `int#ref=dso.TbEnemy?` | 不报 |
| 限定取值 | `int#set=5` / `int#(set=1,2,3)`（**待核对**：当前 8 张表没有一列用过） | 报错 |
| 资源路径 | `string#path=unity`，填**相对 `Assets`** 的路径 | 不报 |

- 限制符写在**类型行**，不写数据格；多值必须**括号 + 逗号**，用 `;` 直接报错。
- ⚠️ `!` 的含义是"**不许是默认值**"（数字的默认值是 `0`），不是"必填"：这一列的合法取值里包含 `0` 时**不要加 `!`**。详见《技术文档_配表管线》§3.1.1。
- 🔴 程序**只能加载 `Assets/Resources/` 下**的资源。导表期只校验"文件在 `Assets/` 下存在"，不校验它在 `Resources/` 下——填了别处的路径**导表不报错**，将来接上取图的代码就是运行期加载失败。资源一律放 `Assets/Resources/` 下再填。

### 加表

表格文件自己建，但**必须登记**：在 `ConfigWorkspace/Data/__tables__.xlsx` 加一行。

| 列 | 填什么 | 例 |
| :-- | :-- | :-- |
| `full_name` | 模块名 + `Tb` + 记录名 | `dso.TbEnemy` |
| `value_type` | 记录类名 | `Enemy` |
| `read_schema_from_file` | 填 `1`：字段定义从这张表自己的表头读 | `1` |
| `input` | 表格文件名 | `enemy.xlsx` |
| `index` | 主键字段 | `id` |
| `group` | 填 `c`（留空 = 属于所有分组） | `c` |
| `output` | 生成的数据文件名；**留空则默认 `<模块>_<表名>`** | `dso_tbenemy` |

> 当前 8 张表的 `output` 全部留空，一律走默认。上表之外还有 `mode` / `comment` / `tags` 三列：`mode` 与 `tags` 留空即可，`comment` 建议填一句中文说明。
>
> 主键不一定是 `id`：`element_rule` 的主键就是 `priority`（`index` 列填 `priority`）。

### 加列

**可以插在任意位置**，包括两个已有字段之间。插入一列 → 填齐 4 行表头 → 逐行补数据格（留空可以，但**数字格留空会变成 `0`**）→ 保存 → 关 Excel → 导表。

![p6](image\p6.png)

### 登记枚举

在 `ConfigWorkspace/Data/__enums__.xlsx`：`full_name` 写完整枚举名（如 `dso.BallType`），**每个枚举项占一行**。

![p7](image\p7.png)

**枚举列的数据填"别名"（中文），不是英文项名**：

| 枚举 | 可选值（填这些） |
| :-- | :-- |
| `dso.BallType`（球种） | `水` / `土` |
| `dso.TileStateType`（格子状态） | `常规` / `泥浆` |

### 战斗相关的六张表

填写口径：**只改数据格，不要动这四行表头**（字段名 / 类型是程序的契约，改字段名会让代码编译不过）。
逐列的"有没有消费者"写在每张表下面 —— **列了但代码里没人读的列，改它不会有任何效果**。先给一句汇总：**这 6 张表里出现的每一个 `name` 列都没有消费者**（`tile_initial` 没有这一列；改 `name` 画面上不会出现任何字），`enemy` 的 `stun_seconds` 已废弃，`tile_initial` 整张表 0 行。另外 `enemy` / `player` / `wave` 三张表**程序都只读 `id = 1`**（`ConfigModule.Ids` 写死默认编号），多填的行当前不会生效。

#### `projectile.xlsx` — 球种（2 行：水球 / 土球）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` | 球种 ID（枚举 `水` / `土`） | 枚举别名 | 水 / 土 |
| `name` | 显示名 —— **当前无消费者** | 文字 | 水球 / 土球 |
| `flight_duration` | 最远一投的飞行时长（秒） | 0.05 ~ 5 | 0.6 |
| `max_height` | 抛物线视觉最高点（世界单位） | 0 ~ 10 | 2 |
| `max_throw_distance` | 最远投掷距离（世界单位） | 0.5 ~ 50 | 5 |
| `min_throw_distance` | 最小投掷距离：鼠标压在脚下时兜底 | 0.01 ~ 5 | 0.4 |
| `tile_state` | **落地后把落点格改成什么状态**（`常规` = 不改） | 枚举别名 | 水=泥浆 / 土=常规 |

> **球本身不造成任何伤害**：伤害与击退一律来自 `tile_state` 表的 `enter_damage` / `enter_knockback`，所以"水球砸中敌人掉多少血"这张表里没有答案。想给土球加效果时先填这一列或找程序加列。
> **加新球种不是加一行就行**：`id` 的取值被枚举 `dso.BallType` 钉死（现在只有 `水` / `土`），投掷入口也只绑了这两个键 —— 先找程序加枚举项 ＋ 加入口 ＋ 加表现。

#### `enemy.xlsx` — 敌人（1 行：白模敌人）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` | 编号（主键）。**同时是预制体寻址**：`Resources/enemies/Enemy_<id>.prefab` | 整数 | 1 |
| `name` | 显示名 —— **当前无消费者** | 文字 | 白模敌人 |
| `max_speed` | 追击满速（单位/秒，玩家实际移动速度是 10） | 0 ~ 50 | 3.6 |
| `hp` | 耐久（几下打碎） | 1 ~ 999 | 3 |

> **这张表只剩 4 列。** 半径 / 加速度 / 击退衰减 / 停止距离 / 脱战距离已按《最新表格与SO规范》搬进调参 SO `Resources/tuning/EnemyTuning.asset`（程序管辖，Play Mode 改即时生效、不用导表）——
> 要调"被撞多远滑多久""贴多近停下""多远脱战""身体多大"，请找程序改那份 SO，**改表不会有反应**（表里已经没有这些列）。
> `name` 只用来给程序里那份敌人配置起个名字，没有读取点。
> ⚠️ **加第二种敌人（精英怪）不是加一行就行**：`id` 还兼作预制体寻址（要先有 `Enemy_<id>.prefab`），行为策略要在 `EnemyBrainFactory` 里分流，运动参数还要在 `EnemyTuning` 里有对应条目（见 `Docs/待办.md`）。

#### `tile_state.xlsx` — 格子状态（2 行：常规 / 泥浆）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` | 状态 ID（枚举 `常规` / `泥浆`） | 枚举别名 | 常规 / 泥浆 |
| `name` | 显示名 —— **当前无消费者** | 文字 | 常规 / 泥浆 |
| `slow_factor` | 踩在上面的速度系数（1 = 不减速） | 0 ~ 1 | 常规 1 / 泥浆 0.45 |
| `duration` | 持续时长（秒，**0 = 永久**） | 0 ~ 600 | 常规 0 / 泥浆 8 |
| `enter_damage` | **进入该状态时**对该格敌人的伤害 | 0 ~ 999 | 常规 0 / 泥浆 1 |
| `enter_knockback` | **进入该状态时**对该格敌人的击退冲量 | 0 ~ 50 | 常规 0 / 泥浆 1.83 |

> ⚠️ 这四列的"常规"行要填 `0`，所以**类型行里不能带 `!`**（`!` 表示"不许是默认值"，填 0 会被判失败）。
> **伤害只在格子状态真的发生转换时结算一次**：同一格再砸一颗球（还是泥浆 → 还是泥浆）**既不扣血、也不刷新那 8 秒计时**（想重新触发，得先让这一格变回常规 —— 等它自己到期 —— 再砸）。"进入"指转换发生的那一刻，不是"每一颗球落地"；开局就站在泥浆上的敌人不会掉血。
> **球不直接造成伤害**：水球只是把格子切成泥浆，伤害与击退是这次转换发生时由本表这两列结算给"站在这一格上的敌人"的。
> **加新状态不是加一行就行**：`id` 被枚举 `dso.TileStateType` 钉死（现在只有 `常规` / `泥浆`），程序里也只实现了泥浆这一种状态行为 —— 先找程序加枚举项 ＋ 加行为实现，再来表里加行。

#### `player.xlsx` — 玩家（1 行）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名（`name` **当前无消费者**） | 整数 / 文字 | 1 / 玩家 |
| `max_hp` | 血量上限 | 1 ~ 99999 | 100 |
| `contact_damage` | 敌人贴身一次造成的伤害 | 0 ~ 9999 | 10 |
| `invulnerable_duration` | 受击后的无敌时长（秒） | 0 ~ 10 | 0.8 |
| `retry_delay` | 打空后到重来之间的停顿（秒） | 0 ~ 60 | 1.2 |
| `attack_interval` | 两次攻击之间的最短间隔（秒） | 0.01 ~ 10 | 0.5 |
| `knockback_impulse` | 受击被推开的冲量 | 0 ~ 100 | 12 |
| `knockback_speed_limit` | 受击期间的速度上限 —— **程序把它当作冲量的上限来夹**，所以填得比冲量小就推不满、填大了等于不限；**与冲量填同一个数**最直观 | 0 ~ 100 | 12 |
| `contact_radius` | 判定"敌人贴上了"的圆心距（世界单位） | 0.05 ~ 10 | 1 |

> `id` 是取行的主键（程序固定取 1 号行），改它会让代码取不到行；`name` 没有读取点。其余 8 列都有消费者。
> 玩家的**移动**数值不在这张表里（走 `Assets/Resources/config/PlayerConfig.asset` 那份 SO），这张表只管血量与受击。

#### `wave.xlsx` — 波次（1 行）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名（`name` **当前无消费者**） | 整数 / 文字 | 1 / 默认波次 |
| `enemies_per_wave` | 每波敌人数 | 1 ~ 100 | 4 |
| `spawn_interval` | 同波内两只之间的间隔（秒） | 0.01 ~ 10 | 0.25 |
| `initial_delay` | 开局到第一波的等待（秒） | 0 ~ 60 | 1.5 |
| `respawn_delay` | 清完一波到下一波的等待（秒） | 0 ~ 60 | 2.5 |
| `spawn_radius` | 出生环半径（世界单位，以玩家为圆心） | 0.5 ~ 50 | 5 |

> `id` 是取行的主键（程序固定取 1 号行），`name` 没有读取点；其余 5 列都有消费者。这张表**一行就够**，多填的行不会生效。

#### `tile_initial.xlsx` — 关卡初始格子状态（**当前 0 行**）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 编号（主键，随便给不重复的整数） | 整数 |
| `cell_x` / `cell_y` | 格子坐标（**必填**） | 整数 |
| `state_id` | 初始状态（枚举 `常规` / `泥浆`） | 枚举别名 |

> 一行 = "开局时把某一格设成某状态"。开局就站在泥浆上的敌人**不会**掉血（伤害的语义是"发生了转换"）。
> **这张表现在是兜底的（0 行）**：初始地块的权威来源已是场景 `Grid/InitialSetup` 笔刷层（`TilemapAdapter.LoadInitialSetupTiles` 先读它）；只有"场景里一个初始地块都没刷"时，程序才回头读这张表。读不到行就什么也不做，也不报错。填了行也会生效 —— 但只作用于"当前场景里真的铺了地板的格"；没地板的坐标被忽略，`state_id` 填 `常规` 的行被跳过（那等于没填）。
> **关卡布局请去场景里刷**（见《美术装配指南》第三层结构），别在这张表里手填坐标：改一张图要填几百行、且没有可视化预览。
> 当前没有「关卡」维度：所有行都作用于当前场景；关卡系统立项后再加 `level` 列。三列都有消费者，`id` 只要求不重复。

## 3. 报错对照

报错原文格式是 `记录 <表全名>[<主键>].<字段>:<填的值> (来自文件:<sheet>@<xlsx 路径>) <原因>` —— **`[]` 里就是那一行的主键**，按它去表里找行。一张表的多个错误会一次全列出来（不用改一个导一次）。

| 报错片段 | 我该改哪一格 |
| :-- | :-- |
| `位置:[D5] abc` / `abc 不是 int 类型值` | `enemy.xlsx` D5。这列只能放数字 |
| `'水球' 不是 enum:'dso.BallType' 的有效枚举值` | 球种列。改成 `水` / `土`（或对应枚举的别名） |
| `<列>:999 … 不在范围:[0.05,5] 内` | 类型行带 `#range=` 的那一列填超范围了（`projectile.xlsx` 里有多列是 `float!#range=…`） |
| `[常规(0)].duration:0 … 是一个默认值` | 这一列的类型行带了 `!`，而 `!` 的含义是"**不许是默认值**"（数字的默认值是 0）。**明确填 0 也会报**。要么填非 0，要么让程序把这一列的 `!` 去掉 |
| `<列> = 9 … 在引用表…中不存在` | 外键（`#ref=`）那一列填了被引用表里没有的编号 |
| `icon:… 找不到对应文件` | 编号 3 那行的图标格。改成存在的路径 |
| `有表格正被 Excel 占用` | 不用改格子。保存并**关闭**名单里的表 |

改完重新导表。Console 里 `[Luban] 完整日志：` 指向的文件有全部输出。
